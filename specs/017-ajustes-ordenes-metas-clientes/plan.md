# Implementation Plan: Ajustes en Órdenes, Metas y Clientes

**Branch**: `017-ajustes-ordenes-metas-clientes` | **Date**: 2026-10-19 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/017-ajustes-ordenes-metas-clientes/spec.md`

## Summary

Three independent slices:

1. **Órdenes (P1)** — remove `OrderStatus.Delivered` from the catalog and from the transition rules (server `OrderService.ValidateTransition` and UI `Index.cshtml.cs` next-status map), restrict receipt marking to Delivering, keep reassignment for Active/Delivering/Completed. A data-only EF migration moves `Delivered` orders to `Completed` and inserts one `OrderStatusHistory` row per migrated order. Relabel the transition button "Enviar" → "Iniciar entrega". The history table in Items maps status keys to Spanish labels (including the legacy `Delivered` → "Entregada"). Non-Pending item rows get a "Ver" button that opens the existing item modal in read-only mode.
2. **Metas (P2)** — commission rules live server-side in one pure static helper (`SalesGoalCommission`), applied in `SalesGoalService` to `GoalDto` (Mes Actual) and `HistoryRowDto` (Histórico). Pages only render rate, amount and status. Mes Actual gets a new info-box; Histórico gets a new "% Comisión" column.
3. **Clientes (P3)** — client-side filtering: the grid loads the full catalog once into a cache. `loadData(filter)` combines the jsGrid column filters with a new global search box (accent- and case-insensitive, trimmed, applied while typing). The cache is refreshed after insert/update/delete.

**Scale/Scope**: Customers number in the hundreds (client-side filtering is fine). The migration touches only orders currently in `Delivered`.

## Design Notes

### Slice 1 — Órdenes

- **Transitions** (`OrderService.ValidateTransition`): `Active → [Delivering, Voided]`, `Delivering → [Completed, Voided]`, `Completed → []`. A request to or from `Delivered` hits the existing message `Transición 'X' → 'Y' no permitida.` (FR-003). `Index.cshtml.cs` gets the same map.
- **Receipt** (`OrderService` ~L169): only `Delivering`; message "Solo se puede marcar recepción en órdenes en estado Entregando."
- **Reassign** (~L345): `Active, Delivering, Completed`.
- **OrderStatus**: delete the `Delivered` static and drop it from `List()`. After the migration no order has `Delivered`, so `FromKey` (used only for current order status) never sees it. The filter in `Orders/Index.cshtml` iterates `List()`, so it drops "Entregada" automatically (FR-008). `ParseFilter` already ignores unknown keys, so an old bookmarked URL with `Delivered` falls back safely.
- **History labels** (FR-005): `OnGetHistoryAsync` returns raw keys. `items.js` renders them through a local key→label map that includes the legacy `Delivered: 'Entregada'`, so old rows read "Entregada" instead of the raw key.
- **Migration** `RemoveDeliveredOrderStatus` (data only), in `Up`:
  ```sql
  INSERT INTO dbo.OrderStatusHistory (Id, OrderId, FromStatus, ToStatus, TransitionDate, Notes, Justification, CreatedAt)
  SELECT NEWID(), Id, 'Delivered', 'Completed', SYSUTCDATETIME(),
         N'Migración automática: el estado Entregada fue eliminado (spec 017).', NULL, SYSUTCDATETIME()
  FROM dbo.Orders WHERE Status = 'Delivered';
  UPDATE dbo.Orders SET Status = 'Completed', UpdatedAt = SYSUTCDATETIME() WHERE Status = 'Delivered';
  ```
  `Down` is intentionally empty (irreversible data fix), with a comment explaining why.
  **Deploy order**: `Program.cs` does not auto-migrate, and `OrderStatus.FromKey` throws on a leftover `Delivered` (Orders list and Items page). Apply `RemoveDeliveredOrderStatus` to production (`dotnet ef database update` or `dotnet ef migrations script --idempotent`) **before or together with** deploying the code. No Transactions or CxP rows are created (FR-004). Raw SQL skips the EF organization query filter, which is correct because the migration applies to every organization.
- **Labels** (`index.js`): `{ Active: 'Activar', Delivering: 'Iniciar entrega', Completed: 'Completar', Voided: 'Anular' }`.
- **Item "Ver"** (`items.js`): when `!isPending`, add `<button class="btn btn-xs btn-info mr-1">Ver</button>` → `openViewItem(item)`. It reuses `openEditItem(item)` for population and then:
  - sets the title to "Ver Ítem";
  - disables every `input, select, textarea` in `#itemModal .modal-body`, including select2 `#item-customer`, `#item-product-type` (also after its async load completes) and the file input;
  - hides `#btn-save-item` and renames Cancel to "Cerrar".
  On `hidden.bs.modal` it restores enabled state, button visibility and labels, so later Pending flows are unaffected (in practice the page is single-status, but the restore keeps it safe). The image preview stays visible, and "Ver Img"/"Reasignar" are unchanged (FR-012). Customer select2 and its options are already loaded in every status (items.js L462–477).
- `isDelivering` (`items.js` L199) becomes `orderStatus === 'Delivering'` (FR-006).

### Slice 2 — Metas

- `SalesGoalCommission.For(decimal basePct)` → `(decimal Rate, string Status)`:
  - `< 85` → `(0, "red")`
  - `< 86` → `(2.5, "yellow")`
  - `<= 110` → `(5, "green")`
  - else `(6, "green-plus")`
  
  `Amount(actual, rate) = Math.Max(0, Math.Round(actual * rate / 100, 2, AwayFromZero))`.
- `GoalDto` adds `CommissionRate`, `CommissionAmount` and `CommissionStatus`. The base is always `CompliancePercentage` (FR-015, corrected 2026-10-20), already rounded to 1 decimal.
- `HistoryRowDto` adds the same three fields. In `GetHistoryAsync`, every row uses its `CompliancePercentage`; no extra query.
- **Mes Actual**: change the info-box row from 3 × `col-md-4` to 4 × `col-md-3` and add `#commission-total` as `<span class="info-box-number">` holding the rate, plus `<small id="commission-amount">` holding `(sign amount)`. Classes: reuse `goal-red`/`goal-yellow`/`goal-green`. `green-plus` → `goal-green goal-highlight`, where `.goal-highlight { box-shadow: 0 0 0 3px #155724, 0 0 12px rgba(40,167,69,.8); }`.
- **Histórico**: new `<th class="text-right">% Comisión</th>` after "% Cumplimiento". The cell shows a colored badge with the rate (`badge-danger`/`badge-warning`/`badge-success`, with a `goal-highlight`-style border for `green-plus`) followed by `<small>(sign amount)</small>`. The existing `fmtPct` already shows 1 decimal.

### Slice 3 — Clientes

- `Customers/Index.cshtml`: add `<input id="customer-search" type="search" class="form-control" placeholder="Buscar por apodo, nombre, teléfono, email o dirección">` above `#jsGrid`.
- `customers/index.js`:
  - `var cache = null; function norm(s) { return (s || '').toString().normalize('NFD').replace(/[̀-ͯ]/g, '').toLowerCase().trim(); }`
  - `loadData(filter)`: if `cache` is null, `$.get('?handler=Load')` and store the result, then return the filtered list. A row passes when every non-empty column filter is contained in its field (normalized), and the global term (if any) is contained in at least one of the 5 fields.
  - Global input: `on('input')`, debounced 200 ms, calls `$('#jsGrid').jsGrid('search')`, which re-calls `loadData` with the current column filters.
  - `onItemInserted` / `onItemUpdated` / `onItemDeleted`: set `cache = null` and call `jsGrid('search')`, so the list reflects the server and still respects the filters (FR-022).
  - Empty result: jsGrid's `noDataContent: 'No se encontraron clientes'`.
